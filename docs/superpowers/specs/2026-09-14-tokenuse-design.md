# TokenUse 桌面应用设计草案

状态：用户已授权复查后开工，2026-09-14 完成第二次规格复查，进入实施。本文描述实现范围，不代表所有功能已经实现。

## 目标与环境

为个人提供统一的 Token 使用情况看板。首版只面向 Windows，并支持配置已安装的 WSL 发行版作为只读数据源。单用户、本机使用，不同步到云端。

首版原生采集覆盖 Codex、Claude Code 和 OpenClaw 的本地 JSONL。Cursor 只提供 CSV 导入，不承诺自动读取 Cursor 本地库或账号账单。服务商包括 DeepSeek 官方和用户提供的中转站预设。用户已明确暂不考虑 RAG 项目，首版也不实现本地 API 转发服务。

### 首版明确不做

- 自动启动、预算提醒、汇率自动更新。
- 读取或存储 API Key、`auth.json`、Cursor 登录态，以及任何账户、余额、账单接口。
- 自动抓取中转站价格；不按高峰/低谷时段自动切换单价。
- 原生解析 Cursor `state.vscdb`、Cursor 账号 CSV 以外的内部库。
- 解析 OpenClaw 较新版本可能改用的 SQLite session store；只读 JSONL 转录。
- macOS / Linux 安装包、多用户、团队共享、实时拦截请求。

## 首版界面

三个页面：

- 总览：本地日历日的今日、本地日历月的本月 Token 用量，支持按小时、日、周、月查看趋势，展示一天内各时段的使用分布，以及有完整价格依据的费用估算。
- 用量明细：按时间、调用工具、服务商、模型和可获取的项目信息筛选；支持分页和导出 CSV。
- 数据源设置：本地或 WSL 记录位置、服务商预设、连接状态和价格规则。

支持后台刷新和托盘常驻。托盘提供打开主窗口、立即刷新和退出。应用必须保持运行才会后台刷新；首版不注册开机启动，也不做预算提醒，以减少初次配置步骤。

总览只展示原始用量和费用估算。平台账单、账户余额和订阅额度首版不采集、不展示，避免被误认为已经接入。界面采用中文，默认跟随系统明暗主题。首次启动引导选择检测到的数据源，展示将读取的位置，并建议为每个数据源指定默认服务商。正常启动不填充演示用量。

从明细导出的 CSV 带 TokenUse 导出标记；再次导入时默认拒绝当作新用量，除非用户明确选择“作为独立来源导入”。

### 各时段使用统计

首版包含以下时间统计，均针对已采集或导入的记录：

- 时间范围：提供今日、昨日、最近 7 天、最近 30 天、本月，以及自定义起止日期和时间。最近 7 天和 30 天均包含今天，按本地日历日计算。
- 时间趋势：支持按小时、日、周、月分桶。今日和昨日默认按小时，最近 7 天、最近 30 天和本月默认按日。展示选定范围内随时间发生的用量变化，不能把不同日期的同一小时自动合并在这张图上。
- 一天内使用分布：将选定日期范围内的记录按本地钟表小时汇总到 00–23 时共 24 个桶。例如选择最近 7 天时，“09:00–10:00”表示这 7 天每天该小时的已记录用量之和，明确标注为合计，不标成单日用量或每小时平均值。
- 时段汇总：固定提供凌晨（00:00–06:00）、上午（06:00–12:00）、下午（12:00–18:00）、晚上（18:00–次日 00:00）四个互不重叠的时段，显示各时段 Token 用量及占已记录总用量的比例。首版不提供自定义时段名称和边界；精确查看其他时段使用明细的日期时间筛选。
- 图表交互：时间趋势的桶支持点击跳转到对应日期时间范围的明细；一天内分布和时段汇总的桶支持按“原日期范围 + 每日钟表时段”查看明细，不能跳转成一个跨多日的连续时间段。
- 所有时间视图使用同一组工具、数据源、服务商、模型和项目筛选条件，显示总 Token，并在已有分项时展示输入、输出、缓存明细。有完整价格规则时可切换费用估算；不同币种不合成一个金额。

时间趋势一次最多生成 1,000 个桶。所选粒度超出限制时提示缩小时间范围或选择更粗粒度，不静默截断或省略中间时段。

“使用时段统计”不意味着按峰谷时间切换价格。首版价格规则仍按生效日期匹配，不引入按小时自动计价。

## 服务商可配置项

服务商配置与调用工具配置分开。同一个 Claude Code 数据源可能调用多个服务商，同一个服务商也可能被 Claude Code 和 OpenClaw 共同使用。

每个服务商条目包含：

- 显示名称、官方网站、价格页链接。
- API Base URL：独立选填，不能由首页或价格页未经验证地推导。未填写时不伪造地址，也不影响已有日志采集。
- 协议备注：允许记录 OpenAI 或 Anthropic 兼容协议。首版不根据该配置发起推理或账户请求。若同一官方文档给出多个兼容入口，只把用户选填的那一个存为 API Base URL，另一个写在备注。
- 首版日志采集和 CSV 导入不需要 API Key，不要求用户填写或导出凭据。以后如接入账户查询，另行设计安全存储。
- 模型名称映射：先精确匹配，再使用用户添加的别名。不根据模型名猜测服务商。
- 价格规则：按服务商、模型、币种、生效起始日期定义。计价单位统一为每 1,000,000 Token。可分别填写输入（未命中缓存）、缓存读取、缓存写入、输出、推理输出。未使用的分量可以留空。
- 启用状态：关闭后不再作为新记录的默认归属，历史快照和已归属记录仍可筛选。

采集数据源另行显示：路径是否可读、记录格式是否受支持、最后成功同步时间，以及数据完整性说明（例如部分会话没有用量事件、CSV 只有总量）。服务商网站可访问不能显示为 API 已验证，首版不测试推理和账户接口。

推理 Token 若无单独单价，默认回退到输出单价；用户可关闭该回退。关闭后，只要该记录出现的计费分量缺少单价，整条费用为未知，不把缺项当零。只有金额、没有 Token 的记录不反推 Token。

## 首版采集方式与可行性证据

选择本地日志采集配合 CSV 导入，减少现有调用配置的变化。账户接口方案需要分别验证服务商权限，转发方案需要保持服务运行和修改请求地址，因此均不纳入首版。

### 默认检测路径

首次启动只把存在且可读的目录列为候选项，允许用户改路径或跳过。环境变量若存在则优先：

| 工具 | Windows 默认 | WSL 默认 | 覆盖变量 |
| --- | --- | --- | --- |
| Codex | `%USERPROFILE%\.codex\sessions\` | `~/.codex/sessions/` | `CODEX_HOME` |
| Claude Code | `%USERPROFILE%\.claude\projects\` | `~/.claude/projects/` | `CLAUDE_CONFIG_DIR` |
| OpenClaw | `%USERPROFILE%\.openclaw\agents\` | `~/.openclaw/agents/` | 用户指定 |
| CSV | 无默认，由用户选择文件 | 无 | 无 |

OpenClaw 若存在旧目录 `~/.clawdbot/`、`~/.moltbot/` 或 `~/.moldbot/`，列为只读候选项，不自动合并到当前目录。Cursor 不加入自动检测。

Windows 的 `C:\Users\...\` 与 WSL 的 `/home/...` 通常是两套安装、两套日志，必须分成两个数据源。只有路径解析到同一文件时才视为别名，例如 `C:\Users\me\.claude` 与 `\\wsl.localhost\Ubuntu\mnt\c\Users\me\.claude`。规范 Windows 侧 WSL 路径为 `\\wsl.localhost\<发行版>\<linux 绝对路径>`，不要用已弃用的 `\\wsl$\` 作为唯一形式。

WSL 数据源由用户选择发行版与 Linux 绝对路径；应用通过上述 Windows 可访问路径读取，不修改 Linux 内工具，也不为了扫描而启动未运行的发行版。未运行或不可访问时显示离线并允许重试。

### 2026-09-14 只读抽样与公开格式

检查只输出字段结构，没有输出对话正文或凭据。官方 Codex 文档本次访问返回 HTTP 403，因此可行性结论以本机抽样和第三方格式观察为依据，不作为稳定官方接口承诺。

- Windows Codex 的 JSONL 含 `payload.info.total_token_usage` 和 `last_token_usage`，字段包括输入、缓存读取、缓存写入、输出、推理输出及总量。公开资料中的常见根目录为 `${CODEX_HOME:-~/.codex}/sessions/YYYY/MM/DD/`。部分交互式 TUI 会话可能不写 `token_count`；这类会话计入“无用量事件”，不能当成零消耗。
- Windows 和 WSL Claude Code 的记录含 `message.usage`，字段包括输入、输出、缓存创建和缓存读取。常见根目录为 `~/.claude/projects/<项目目录编码>/<session>.jsonl`。同一助手回复可能拆成多行，`message.id` 与 `requestId` 相同，输入类字段重复，`output_tokens` 单调递增；归并时保留最后一次用量。
- OpenClaw 记录含 `message.usage`，字段包括 `input`、`output`、`cacheRead`、`cacheWrite`、`totalTokens` 和可选 `cost`。常见路径为 `~/.openclaw/agents/<agentId>/sessions/<sessionId>.jsonl`。并非所有抽样文件都有用量记录。日志里若带显式 `provider` 字段，可作为归属提示，仍须映射到用户配置的服务商，不能根据模型名猜测。
- Cursor 的本地数据目录存在，但本机尚未验证完整用量字段；公开实现也表明本地 bubble 计数经常不完整，准确数字多来自 Cursor 账单或导出。首版只提供 CSV 导入，不承诺自动读取完整用量。

### 适配器行为

Codex、Claude Code 和 OpenClaw 适配器读取 JSONL，按文件规范路径加字节偏移增量更新；处理尾行尚未写完、文件截断和重复扫描。源文件被删除或轮转时，已入库统计保留，只停止继续读取该文件。

- Codex：优先使用 `last_token_usage`。若只有累计值，按同一会话内相邻 `total_token_usage` 的差计算增量；累计值变小或会话更换视为计数重置，不把重置后的累计值再减出负数。同时核对单次事件字段，避免累计值与增量双计。
- Claude Code：以来源、`message.id` 和 `requestId` 归并，保留更新后的用量。
- OpenClaw：以来源和消息/行标识归并。日志中的 `cost` 记为来源申报费用，不与本地价格估算混写成同一个数字。
- 解析时只提取统计所需字段，默认不保存对话正文。

CSV 导入提供预览、列映射和错误行统计。至少需要时间，以及总 Token 或输入/输出分项；支持可选模型、缓存、费用、服务商和记录标识列。只有总量时分项保持未知；只有金额时不可推算为 Token。去重键优先用记录标识列，否则用规范化后的时间、模型、分项、费用和服务商组成的行指纹。重复导入相同记录不会重复计数。

仅配置服务商网址不能获得账户用量或历史调用。

## 统一用量事件

各适配器输出同一形状的事件，统计层只消费该形状：

- 稳定去重键、数据源、调用工具、UTC 发生时间。
- 可选：模型、项目、服务商。
- Token 分量：未缓存输入、输出、缓存读取、缓存写入、推理、来源总量。缺失分量保持未知，不补零。
- 费用：来源申报（含币种）与本地估算分开；估算在价格不足时为未知。
- 原始计数字段可保留作解释，不含正文。

项目仅在来源明确给出时填写：Claude Code 的项目目录名或 `cwd`，Codex 的 session `cwd`，OpenClaw 的 agent 或 session 标识，CSV 的可选项目列。无法确定则为未知。

## 统计口径

- 调用工具、服务商、模型和项目是同一次调用的不同维度，不分别累加为多次消耗。
- 原始用量、费用估算、来源申报费用分别表示。未知值显示未知，不显示为零。来源申报费用和本地估算同时存在时并排标注来源，不互相覆盖。
- 缓存 Token 是否已经算在输入内，由适配器按来源协议声明；统计层写入归一化分项，并保留原始字段以便核对。展示总 Token 时，有来源总量用总量，否则用归一化分项求和，并在完整性说明中写清算法。
- 归一化后的输出不包含单独列出的推理 Token；若来源的输出已含推理，先扣除推理再计入两个互斥分量。来源没有提供总量且必需分项不完整时，总量保持未知，可显示已知分项小计，不能把小计称为完整总量。来源数值无效、为负数或包含关系矛盾时标记异常。
- Codex 同一会话的重复累计快照即使再次携带 `last_token_usage`，也不产生第二笔用量；只有明确增加或重置的计数才进入增量统计。
- 优先使用请求或事件标识去重。路径别名只用于同一文件的不同写法。Windows 安装与 WSL 安装默认分开，以免两套日志被合成一份。不同导入来源无法可靠关联时，允许设置是否参与汇总，并提示潜在重叠。
- 无法确定服务商或项目的记录保留为未知归属，不根据模型名称猜测服务商。日志显式写出的 provider 只作为映射输入。
- 支持给数据源配置默认服务商，默认只对**尚未归属**的后续新记录生效；不改写已经有归属的历史。历史记录批量改归属必须明确选择日期范围，避免把切换中转站之前的用量改错。
- 不同币种分别汇总。首版不做汇率折算；若以后提供折算，必须标明汇率来源与时间。
- 费用估算按调用发生时刻的本地日期，匹配该服务商、该模型在生效起始日不晚于该日的最近一条价格规则。余额变化不能直接当成 Token 费用。
- “今日”“本月”按查询时操作系统时区的日历日、日历月。事件以 UTC 存储，聚合时转换到该时区。跨日以事件时间戳落在哪一个本地日历日为准。
- 时间范围查询统一使用左闭右开区间 `[开始, 结束)`。仅选择结束日期时，界面包含该日，查询终点转换为该日之后一天的本地零点；精确结束时间则不包含该时刻。小时、日、周和月的桶在相应本地日历边界对齐，周一为一周开始；边缘桶只汇总所选范围内的事件并标记为部分时段。
- 时段归属依据来源用量事件的时间戳，不使用文件修改时间或导入时间。一条跨小时调用的用量整体归到其事件时间，无法由汇总日志还原调用过程中每分钟的实际消耗。CSV 缺少时间戳时不能按时间导入；时间戳只有日期时允许按日或更粗粒度统计，但排除在小时、每日时段分布和精确时间筛选外，并说明排除数量。不能默认为零点产生虚假的凌晨高峰。
- CSV 时间带时区偏移时使用该偏移；没有时区时，导入预览要求明确选择解释时区，默认显示当前系统时区并保存该选择。Windows 和 WSL 数据统一转换成 UTC，不重复叠加时差。系统时区改变后重新聚合显示，不修改原始事件时间。
- 同一 CSV 文件再次导入时恢复原解释时区；已经入库记录后拒绝改用另一时区，避免偏移后的重复记录。如果此前没有成功导入任何记录，允许更正时区。没有逐行币种列的费用可以使用导入界面中明确选择的默认币种。
- 夏令时切换时，时间趋势中重复的本地小时以 UTC 区间区分，并显示时区偏移；不存在的小时不伪造事件。一天内 24 小时分布按钟表小时归并重复小时并标注口径。
- 图表标为“已记录用量”。没有事件的桶显示“无记录”；来源离线、缺少用量事件或时间精度不足时保留完整性提示，不能声称该时段实际未使用。仅有金额或缺少计价字段的记录不伪造完整费用；费用汇总有缺项时显示已知小计及未计价记录数量。

## 本地数据与边界

统计和配置保存在 Electron 应用的本机 `userData` 目录，使用 SQLite。默认不保存对话正文。解析现有日志时只提取统计所需字段。

路径不可访问、发行版未运行、格式不支持、没有用量事件、部分字段缺失，应分别提示，并保留其他来源的正常结果。不要用“数据过期”描述本地日志；同步落后显示为“上次成功同步”时间，由用户判断是否需要刷新。

没有日志、接口或导出记录支持的历史使用量无法恢复。自动拉取中转站价格和账户余额不属于首版范围，首版提供手动价格配置。

## 架构与数据流

采用 Electron + React + TypeScript，使用 SQLite 保存本地统计和配置。选择 Electron 是因为 Windows 窗口、托盘和 Node 文件生态成熟，便于首版处理 JSONL 与 WSL 路径；代价是安装包和内存占用相对较大。Tauri 或不做图表的原生 Python 窗口都能读日志，但不作为本次图表界面的首选。

- 桌面主进程：管理窗口、托盘、文件选择、采集调度和数据库。
- 数据源适配器：独立解析 Codex、Claude Code、OpenClaw 和 CSV，输出统一用量事件。
- 统计层：计数归一化、幂等入库、服务商归属、价格匹配，以及按本地时区聚合。
- 界面进程：通过受限 IPC 请求统计和修改设置，不直接访问文件系统，不启用 Node.js。

数据流为记录文件或 CSV → 解析和验证 → 归一化与去重 → SQLite → 汇总和明细界面。

刷新策略：本机路径优先用文件监视，写入停止后防抖再增量读取；监视不可用时每 30 秒轮询。WSL 只在目标发行版已运行时读取，默认每 2 分钟轮询，避免周期性唤醒未运行的发行版。手动刷新始终可用。采集并发受限，单个来源失败不阻断其他来源。
